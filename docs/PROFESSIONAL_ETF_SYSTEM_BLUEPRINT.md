# 专业化 ETF 研究系统方案

> 结论先行：本仓库当前不能被称为“已验证有效的专业投研系统”。它已经具备数据采集、因子、轮动雷达、持仓建议和部分回测接口，但当前本地验证显示：因子池存在冗余，综合研究信号回测为负，walk-forward 样本外验证没有有效窗口。因此，现阶段只能定位为研究原型；任何“买入/卖出/保证有效”的表述都必须禁止。

本文的目标是给出一个可审计、可回测、可逐步接近券商研究平台风格的完整方案。这里的“类似华泰证券系统”只指专业券商常见的研究工作流、参数治理、风险控制和报告形态，不代表复制或知晓华泰证券的内部系统。

## 1. 系统定位

系统应定位为“中国上市 ETF 行业/主题轮动研究平台”，不是自动交易系统，也不是预测价格的黑箱模型。

最终交付物分为六层：

1. 数据可信层：行情、基金资料、估值、流动性、费用、折溢价、跟踪误差、持仓和人工输入。
2. 因子研究层：因子定义、参数来源、异常值处理、中性化、IC/分位检验。
3. 轮动决策层：行业/主题池排名、状态标签、观察/配置/回避分层。
4. 组合建议层：相对当前持仓输出加仓、减仓、新增、持有不变。
5. 回测核验层：点时数据、次日成交、成本、滑点、样本外、参数稳定性。
6. 报告审计层：每日简报、参数表、数据质量、回测证据、不能使用的结论。

专业系统必须满足一个原则：没有数据来源的字段不打分，没有样本外验证的策略不称有效，没有成本建模的收益不称可实现。

- `可暂用`：有公开研究依据，并且当前本地有部分验证支持。

- `未验证/需替换`：当前工程默认或人工中性值，不应包装成专业结论。

| 调仓频率 | monthly | 月度 | 月度为基准；周度只做观察 | 降低成本和过拟合 | 可继续验证 |

## 4. 信号与打分方案

### 4.1 一级评分框架

生产版不应直接使用当前固定权重：

```text
当前 total_score =
30% 景气 +
25% 动量 +
15% 估值 +
10% 结构 +
10% 流动性 +
10% 风险
```

这组权重是合理的工程起点，但不是已经证明有效的专业参数。专业做法应改为“先验权重 + 回测门槛 + 样本外锁定”：

1. 先验权重只用于初始研究，不用于生产发布。
2. 每个大类必须有 IC、分位收益、换手、相关性和样本外结果。
3. 通过验证后冻结一版参数，后续改动必须登记实验编号。
4. 每日报告必须显示“参数版本号”和“最近一次验证结果”。

### 4.2 建议生产权重候选

在未完成样本外验证前，只建议作为待测版本：

```text
candidate_v1 =
25% 相对动量
15% 趋势确认
15% 流动性/容量
15% 风险约束
15% 估值赔率
15% ETF结构质量
```

理由：

- 当前因子相关性显示，`momentum_60d`、`risk_adjusted_return_60d`、`trend_strength_20_60d` 高度冗余，不能重复重仓。
- 当前估值和结构数据质量不足，所以不能把它们当强 alpha；但专业 ETF 选择又不能完全忽略它们。
- 流动性和风险应该更多作为约束项，而不是简单 alpha 加分。

## 5. 回测与上线门槛

### 5.1 必须采用的回测规则

1. 点时数据：调仓日只能使用当日及以前数据。
2. 次日成交：信号日收盘生成，下一交易日执行。
3. 成本：至少包括单边 5bp 基准成本；生产版必须加入动态价差和冲击成本。
4. 样本外：必须 walk-forward；不能用全样本 ICIR 直接决定历史调仓权重。
5. 参数登记：每个参数组合都记录，防止只展示最优组合。
6. 生存者偏差：当前 Top100 池存在历史样本选择偏差，必须补历史 ETF 池。
7. 数据缺失：覆盖率不足 95% 的日期不得进入生产回测。

### 5.2 上线门槛

这些门槛是内部治理门槛，不是文献保证值：

| 检验 | 最低要求 |
| --- | --- |
| 数据覆盖 | 交易日覆盖率 >= 95%，核心字段无系统性缺失 |
| 回测长度 | 至少 3 年，最好 5 年以上，且覆盖牛/熊/震荡 |
| 调仓次数 | 月度策略至少 36 次调仓 |
| 因子 IC | 核心因子 Rank IC 均值 > 0.02，IC 正比例 > 55% |
| 分位收益 | Top/Bottom spread 为正，且不依赖单月极端收益 |
| 样本外 | walk-forward OOS Sharpe-like > 0，且多数窗口为正 |
| 成本后表现 | 扣成本后跑赢 510300.SH 和 ETF 等权池 |
| 回撤 | 最大回撤不高于基准，或有明确收益补偿 |
| 过拟合 | 记录所有试验，计算 PBO/DSR 或等价多重检验惩罚 |
| 换手 | 月均换手与成本后收益匹配，不允许高换手低 alpha |

## 7. 当前存在的过度设计

1. 固定六模块综合分过度精细：估值和结构没有真实专业数据，却给了确定权重，容易制造虚假精确感。
2. 动量相关因子重复计分：动量、风险调整收益、趋势强度高度相关，叠加后等于重复押注同一个方向。
3. 市场状态暴露 95/75/45 是工程默认：目前没有通过样本外验证。
4. 相关簇风控看起来专业，但在样本短、标的少时容易不稳定。
5. 当前回测用全样本 ICIR 作为权重基础，存在潜在前视问题；生产回测必须改成滚动训练。
6. 状态标签过多：`主线候选/重点跟踪/谨慎观察/继续观察/价值陷阱` 等可读性好，但统计显著性未必足够。
7. AKShare 全量刷新链路过重且不稳定；生产系统应该使用可重试、可断点续传、可审计的数据任务。

## 8. 专业化重构路线

### Phase 0：冻结宣传口径

- 报告只允许说“研究观察”“模型提示”“未通过验证”。
- 禁止写“有效”“买入”“卖出”“确定性机会”。
- 每日报告顶部显示数据状态、覆盖率、参数版本、最近验证状态。

### Phase 1：数据可信化

- 建立 `data_quality_gate`：覆盖率、最新交易日、缺失标的、缓存比例。
- 新增 `instrument_master`：ETF 上市/退市、类型、跟踪指数、费用率、规模。
- 新增 `execution_cost`：成交额、估计半价差、冲击成本。
- 新增 `valuation_inputs`：指数 PE/PB/股息率分位，人工输入必须带来源和日期。

### Phase 2：参数注册表

每个参数必须写入注册表：

```text
parameter_id
value
allowed_range
source
reason
backtest_id
status: candidate / validated / rejected
owner
updated_at
```

没有 `validated` 的参数只能用于研究版报告。

### Phase 3：回测升级

必须新增：

- 历史 ETF 池构建，避免当前 Top100 回看过去。
- 滚动训练权重，禁止全样本权重回填历史。
- 动态交易成本。
- Walk-forward 与参数网格日志。
- PBO/DSR 或至少多重试验惩罚。
- 与基准、等权池、持有不动组合对比。

### Phase 4：策略收敛

先做三条简单策略，而不是一开始全模块混合：

1. 风险管理轮动核心池：纯数据核心池 + `risk_score >= 60` + 市场状态/集中度约束。
2. 行业/主题相对动量策略。
3. 相对动量 + 估值/结构过滤策略。

只有当简单策略通过样本外后，再组合成综合分。

### Phase 5：纸面跟踪

上线前至少 30-60 个交易日纸面跟踪：

- 每日保存信号快照。
- 每周复盘模型建议与真实表现。
- 记录未执行原因、数据异常和人工覆盖。

## 9. 最小可执行生产版本

如果现在要做一个最诚实的生产雏形，建议只启用：

1. 行业/主题 ETF 池。
2. 数据质量门槛：当日覆盖 >= 95%，否则只出降级报告。
